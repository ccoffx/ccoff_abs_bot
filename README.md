# 昔风听书助手

昔风听书的 Telegram 用户管理助手，连接 Audiobookshelf，提供账号管理、续期与社群互动功能。

项目仓库名使用 `ccoff_abs_bot`，英文程序标识使用 `ccoff-abs-bot`。

用户使用说明见 [用户使用指南](docs/user-guide.md)，代码分层与功能入口见 [项目目录说明](docs/project-layout.md)。

## 项目结构与开发

```text
main.go                 程序启动入口
internal/
  app/                  启动、消息路由、管理后台和定时任务
  account/              注册、绑定、续期、邀请、签到和账号福利
  books/                求书工单、入库采集和公告
  game/                 斗气、药园、宗门、秘境、世界 Boss 和听书修为
  activity/             抽奖、红包、盲盒和寻宝
  market/               交易行和卡密回收
  model/                数据库模型，按业务分类
  storage/              数据库、索引、钱包事务、审计和公共数据操作
  telegram/             消息发送、菜单、回调、会话、权限和并发控制
  abs/                  Audiobookshelf API 客户端
  config/               环境变量配置与校验
  security/             安全令牌、哈希和随机数
  backup/               数据库备份与加密
  metrics/              运行指标
  textfmt/              文本转义、脱敏和解析
scripts/                Docker 启动脚本
docs/                   用户指南和目录说明
```

开发与 CI 使用 Go 1.26.10，以及支持 CGO 的 C 编译器（SQLite 驱动需要）。推荐在 Mac 使用独立测试 Bot 与内置模拟 ABS，无需测试群和额外 ABS 服务：

```sh
./scripts/test-bot.sh init
./scripts/test-bot.sh run
```

`run` 直接编译运行源码，读取 `.env.test`，按 `Ctrl+C` 停止，无需 Docker。脚本也支持项目 `.tools/go/bin/go` 工具链。需要使用 Docker 验收时改用 `./scripts/test-bot.sh up`。

验证和构建也从根目录执行：

```sh
go test ./...
go vet ./...
go build -o ccoff-abs-bot .
```

也可以执行 `./scripts/check.sh` 完成自动测试、竞态检查、静态检查与部署演练。测试保留在相应包内，跨模块测试位于 `internal/app/`。详见 [开发与测试指南](docs/testing.md)。

正式设备使用 GitHub Release 中的部署包，通过 `./deploy.sh update v1.0.0` 拉取固定版本运行，无需源码、Go 或 AI。正式 Compose 不再从源码构建，`.env` 与 `data/` 继续作为正式配置和数据位置。详见 [部署、发布与恢复指南](docs/deployment.md)。

## 邀请码注册有效期

- 邀请码注册预校验读取数据库失败时会提示稍后重试，不会把系统故障误报为邀请码无效。
- 邀请码注册默认有效期由 `ACCOUNT_VALID_DAYS` 控制，当前默认 `30` 天。
- 如果同一 Telegram 用户曾经注册过并保留本地档案，再次使用邀请码注册时，账号有效期至少会补到本次注册默认有效期；若旧有效期更长，则保留更长的旧有效期，不叠加、不缩短。

## 开放注册与服务补偿

- 超级管理员可在私聊管理面板通过 `超级管理员控制台 → ⚙️ 系统配置 → 🚪 开放注册` 使用 `开放注册`，临时允许用户不输入邀请码注册；可选择限制本轮注册总人数，或限制开放分钟数（最长 7 天），同一时间只允许一个开放活动，也可提前关闭。`INVITE_REQUIRED=false` 仍表示全局免邀请码；管理面板开放注册是在 `INVITE_REQUIRED=true` 时提供的临时放行。
- 人数模式在 ABS 开户前事务预占名额，ABS 开户或本地档案写入失败会释放名额；成功注册后名额转为已完成，避免并发超卖。
- 超级管理员可在私聊管理面板通过 `超级管理员控制台 → ⚙️ 系统配置 → 🛡 用户补偿` 使用 `用户补偿`，选择统一发放积分、ABS 有效天数，或两者同时发放，并填写事故播报。任务会对创建时的本地用户快照逐人幂等处理，积分写入流水，完成后私聊用户并向发起管理员回执。
- ABS 天数补偿仅适用于已绑定 ABS 且具有有限到期日的账号；无限期账号保持无限期，未绑定 ABS 的本地积分档案只接收积分补偿。私聊失败不回滚已到账资产；ABS 恢复失败会在管理员回执中提示人工核查。
## 账号安全

- `修改密码` 需要先校验安全码，再同步 ABS 新密码；本地档案暂时读取失败时会提示稍后重试，不会继续校验空安全码或向空 ABS 账号同步密码。
- `绑定账号` 和 `修改用户名` 的 ABS 密码验证有防爆破保护：验证失败累计 `5` 次后锁定 `10` 分钟，锁定期内不受理新的密码验证；验证成功后自动清零失败计数。
- Bot 面板按钮与消息使用同一官方群成员准入校验：退出官方群后，历史面板上的按钮将提示"请先加入官方交流群"，不能再触发功能。
- `账户安全`、换绑安全码校验、仅解绑和删号注销的安全码校验都会先读取本地档案；读取失败时会提示稍后重试，不会误当成未绑定或继续执行高危动作。
- `注册账户`、`绑定账号`、`听书报告` 和 `删号注销` 都会先确认本地档案状态；读取失败时会提示稍后重试，不会误当成未注册、未绑定或直接执行注销。`听书报告` 读取 ABS 主统计失败或解析失败时会提示稍后重试，不会误显示为暂无收听；累计实际听书优先使用 ABS 官方 `totalTime`，今日实际听书按北京时间当天 `days` 明细及已落库的当天统计展示，均保留两位小数；仅书籍完成/在听进度读取失败时，报告保留时长信息并把对应数量显示为“读取失败”。

## 白名单卡密

- 超级管理员私聊进入「卡密续期 → 生成白名单卡」，或发送 `生成白名单卡`，输入数量（1–100）、原因并回复 `确认生成白名单卡`。卡密格式为 `WL-` 加随机字符串，数据库仅保存哈希及脱敏预览，生成与审计一同提交。
- 用户私聊进入「账号服务 → 兑换白名单」，或发送 `兑换白名单` / `使用白名单卡`，输入卡密后回复 `确认兑换白名单`。仅已有正式听书账号可兑换；配置了指定群组时须仍在群内。每张卡仅可成功核销一次，成功后获得现有永久白名单权限，免除账号生命周期封禁和自动清理；此前已暂停的账号仍需管理员恢复。
- 已是白名单、超级管理员、体验账号或未绑定听书账号的用户不能兑换，失败不消耗卡密。核销、白名单设置及审计在同一事务中完成；白名单卡不提供积分购买、回收或交易行上架。持有卡密者可兑换，请只交给指定用户。

## 积分兑换

- 邀请码和 30 天续期卡兑换会先读取当前价格配置；读取或解析失败时中止兑换，不会按默认价扣分。兑换成功后会私聊发送卡密；续期卡会提示是否二次确认后立即使用，确认后直接为当前正式账号延长有效期。兑换邀请码时，只有新人体验账号或尚未注册 ABS 账号才会提示是否立即使用：体验账号确认后转正，未注册账号确认后进入开户注册流程并跳过再次输入邀请码；已有正式账号不会出现直接使用提示。积分兑换的邀请码和续期卡均登记归属，使用、回收和上架仅限当前持有人；所有经过交易行成交的本服卡密都在成交事务中转移归属，买家可继续自用、回收或转卖，旧持有人的明文或旧回收报价不再有效。管理员生成或权益盲盒产出的未登记归属、未经过交易行成交的卡密采用持有码规则。

## 突破互道

- 普通概率突破确认后，在官方交流群招募互道 60 秒，最多 5 人，满员提前渡劫；每人增加 1 个百分点，合计最多 +5 个百分点，最终成功率不超过 95%。无人互道仍按基础成功率执行；必成/保底突破不开放互道，未配置交流群时直接突破。
- 互道者点击前可看到完整风险说明，参与立即扣 5 分；突破成功到账 10 分（净赚 5），失败不返还、不额外扣费（净损失 5）。仅有效未暂停的正式账号且至少斗者可参加，不能互道自己；每人北京时间每天最多 3 次，取消退款的局不占额度。
- 突破者可立即渡劫或取消；突破资源在结算时复核和扣除，条件变化无法执行会取消并原额退还互道投入。规则快照、参与记录、截止时间均持久化，重启会继续处理；突破结果、主资源消耗、互道到账和结算审计在同一事务提交，重复执行不会重复发奖。

## 播放异常风控

- 后台每日北京时间 00:10 后开始播放异常风控，主动刷新 ABS 原始播放时长并检测“昨天”和“前天”，不使用天道压制后的净修为；跨日会话读取或修正持久化失败时不执行告警、冻结，也不标记该批次完成；未完成批次每 5 分钟重试，已成功告警或冻结的用户不会重复处理。备份与账号生命周期巡检仍在 03:00 后执行。
- 风控从 `listening_abuse_effective_start_day` 记录的北京时间日期起算；生效日前的历史收听时长既往不咎，不参与连续两日判断。
- 首次初始化风控生效日写入失败时，会跳过本轮巡检并通知超级管理员，不会拿未持久化的临时日期继续扫描。
- 后台读取风控生效日或末次扫描日失败时，会跳过本轮巡检并记录最近错误、通知超级管理员；状态不明确时不会冻结、恢复或重置生效日。
- 巡检刷新某用户的 ABS 统计失败、缺少 `days` 明细或本地写入失败时，会跳过该用户本轮判断并保留批次待重试状态，不会使用旧缓存或将读取异常当成 0 小时；全部用户处理完成后才登记当日扫描完成。
- 每日净修为以 ABS 官方 `listening-stats.days` 为总量基准；历史会话不得作为实时播放源或墙钟增量补算。前台刷新仍只读取最近 5 页、每页 100 条，避免单次请求阻塞；后台使用 SQLite 游标每批最多推进 5 页并持续扫到历史末尾，不再以 500 条作为总上限。历史扫描同时补记闭关会话凭据，包括不跨日的会话；跨日修正、闭关凭据和页面游标在同一事务中提交，失败时整页回滚。游标会在启动、新注册/绑定/换绑时建立，并每 10 分钟补种；失败后保留页码并延迟重试。
- 对字段完整、低空闲的跨日会话，系统按北京时间墙钟比例守恒分配；对无法知道暂停日期的高空闲跨日会话，不猜测暂停发生时间，只移动数学上必然属于其他日期的最低秒数，并标记为 `bounded/conservative`。字段无效、播放时长超过墙钟、来源日余额不足或数据库/ABS 读取失败时仍保留官方 `days` 原值。
- 后台风控已完成扫描但末次扫描日、扫描时间或最近错误状态写入失败时，会通知超级管理员人工核查，避免下一轮重复扫描同一天。
- 风控仅累计已读取会话中可证明属于该北京时间日期的播放时长下界，不使用比例估算或把不确定余额留在官方来源日后进行处罚。巡检直接计算昨天、前天两个北京时间日期的会话下界，即使官方 `days` 暂无对应日期键，也不会丢弃已证明的时长。会话字段无效、时间不可信或历史页未覆盖的部分不作为处罚证据；该口径可能少计，但不会因跨日估算增加处罚时长。
- 单日可证明的播放时长下界 `> 15` 小时会私聊提醒一次；连续两个自然日都 `> 15` 小时会临时暂停 ABS 听书权限 `24` 小时。
- 单日异常提醒会先在同一数据库事务内创建提醒记录并写入 `LISTENING_ABUSE_WARNING` 审计，事务提交后才私聊用户；若审计或记录写入失败，本轮不会发送未审计的提醒。
- 触发暂停时 Bot 会私聊用户，并在公告群提示账号因播放异常暂停一天；本次风控不扣积分、贡献、声望或修为。
- 暂停满 `24` 小时后后台自动恢复；若账号已到期、已被管理员封禁或绑定的 ABS ID 已变化，则不会自动恢复，避免误解封。
- 自动冻结或恢复失败会写入高危审计；若失败审计也无法写入，会通知超级管理员人工核查。
- `我的信息` 和管理员 `查询用户` 会同时展示本地档案状态、播放异常临停记录和 ABS 服务端 `isActive` 状态；若本地与 ABS 服务端不一致，会提示待核查，不再简单显示为正常。

## 积分抽奖

- 定时抽奖创建支持分钟数，也支持 `YYYY-MM-DD HH:MM:SS` 或 `YYYY-MM-DD HH:MM` 固定时间。
- 固定开奖时间按北京时间解析。
- 创建抽奖的活动、奖品和审计会在同一事务内提交；强制开奖会在开奖事务内写审计；取消抽奖会在同一事务内关闭活动、全额退还参与积分、写退款流水和取消审计。
- `抽奖详情 活动ID` 读取活动、奖品、中奖记录或参与人数失败时会明确提示读取失败，不会把数据库异常误显示为活动不存在、空奖品、无中奖记录或 0 人。
- 领奖暗号错误次数过多会暂停受理；若安全锁状态暂时读取失败，系统会提示稍后再试，不会继续处理暗号。`人工 奖品名称 份数` 可创建联系管理员领奖的特殊奖品；`卡密 奖品名称|卡密内容` 可逐行导入非本服自定义卡密。两类奖品仍沿用开奖后 2 小时内私聊 Bot 发送暗号的领奖流程，自定义卡密仅加密保存并在成功领奖时私发。

## 世界 Boss

- 世界 Boss 击杀成功时生成 `30` 积分 / `10` 份 Boss 红包，并向天道奖池注入 `10` 积分。
- Boss 红包仅限本期已参加 Boss 的修士发送 `抢` 领取；普通积分红包和天道机缘红包不受该限制。
- 制作积分红包输入金额后，如果钱包暂时读取失败，Bot 会提示稍后重新输入金额，不会误判为余额不足；红包份数范围为 `3-100`，总积分仍不得小于红包份数。
- 红包领取成功后的余额或抢空榜读取失败时会明确显示读取失败，不会把数据库异常误显示为 0 积分或空榜。
- 世界 Boss 开启后最后 `15` 分钟停止新道友加入，已参加修士仍可继续造成伤害。
- 群内发送 `参加Boss` 后，Bot 会引用你的消息回复参加结果和失败提示，多人同时参加也能分清各自回执。
- `参加Boss` 需要当前有效且未暂停的 ABS 听书账号；已过期、管理员暂停或播放异常临停中的账号不能参加。
- 结算时若参与者本地账号已不存在或已解绑 ABS，将不计入最终伤害和奖励。
- 实时战榜刷新时也会清理已失效参与者的旧伤害展示，避免血量和排行沿用陈旧伤害。
- 活动进行中，`Boss状态` 和 `Boss排行` 的实时刷新对每人每 `10` 秒限一次，防止频繁刷新拖慢系统；普通查看不受影响。
- 世界 Boss 伤害按参与后 Boss 时段实际听书小时 × `30` ×（1 + 修为加成 + 宗门科技）计算，公告、状态、排行和结算消息会安全展示 Boss 名称，避免特殊字符破坏 Markdown。
- `参加Boss`、`Boss状态` 和 `Boss排行` 读取当前或最近 Boss 状态失败时会明确提示稍后重试，不会把数据库异常误显示为当前没有 Boss。
- `参加Boss` 成功后若参与记录重读失败，当前基线实际听书会显示读取失败，不会误显示为 0 小时；参加记录仍以已提交写入为准。
- `Boss排行`、实时战榜和结算公告读取排行失败时会明确提示读取失败，不会把数据库异常误显示为暂无参与者。
- 有效参与者个人奖励门槛仍为最终伤害 `>= 3`；击杀时有效参与者积分 `+1`、宗门贡献 `+3`，前三名和 Top 10 额外奖励保持原规则。
- 世界 Boss 结算时，斗王及以上的有效参与者按当前大境界有概率掉落「突破到下一境」的至宝（10%），用于斗王之后的突破。

## 宗门秘境

- 宗门秘境分为普通、高阶和限时档位；普通秘境为 `听潮秘境`，高阶秘境默认要求宗门 3 级且参与者至少斗师，限时秘境默认关闭，供运营活动启用。
- 每个宗门每周最多开启 2 次秘境，普通、高阶和限时秘境合并计算，按北京时间周一 00:00 重置。
- 普通秘境开启消耗为 `100 + 宗门等级 * 30` 宗门资金；高阶秘境继续使用独立高阶成本。
- 秘境奖励按开启时保存的档位规则快照结算，管理员后续改配置不影响进行中的秘境；若活动配置快照缺失或损坏，进入和结算会中止并等待修复，不会回退到当前配置继续发奖。
- 结算时若参与者本地账号已不存在或已解绑 ABS，将不计入最终护道者、奖励和掉落。

- 闭关期间仅对闭关开始后的听书增量减缓天道压制：4-8 小时段从 `60%` 提升到 `80%`，8-15 小时段从约 `22.86%` 提升到 `30%`；15 小时后闭关不再提升转化率，18 小时后闭关也不再产生听书修为。基础听书修为与当日所有闭关加成合计最多 `8.5` 小时，闭关仅用于提前达到上限。累计净修为按每日听书统计与持久化闭关记录计算，历史闭关加成跨日、重启后仍保留；跨午夜的闭关按北京时间拆分到各日。闭关奖励仅采用 ABS 会话中可证明落在闭关时间窗内的播放秒数，按会话去重并持久化凭据；无法确定的暂停时段不补算，结束后的播放不计入加成。

- 药草普通回收改为小亏止损口径，按种子成本约 `90%` / 期望产量折算，避免“买种-回收”成为稳定刷分来源；急收行情每日 `22:00` 稳定刷新，并按药草分档限价限额：回气草 `5-6` 分/株、每日额度 `15` 株；青灵叶 `10-11`、额度 `12`；赤阳花 `20-22`、额度 `8`；月影藤 `40-43`、额度 `5`；玄岩参 `60-64`、额度 `3`；紫晶芝 `140-148`、额度 `1`。高阶材料主要价值应来自炼丹消耗，而不是卖给药铺换积分。
- 丹方、聚宝斋、乾坤袋和交易行会展示丹药简要功效；聚宝斋首页直接显示丹药功效速览，货架正文、商品按钮、购买确认和购买成功提示都会带上功效说明或短标识。聚宝斋积分暂时读取失败时显示读取失败，不会误显示为 0。青灵养气丹炼制调整为 `30` 积分炉火费，材料为青灵叶 x8、玄岩参 x3、紫晶芝 x1。
- 吞服丹药事务成功后，如果当前斗气档案暂时读取失败，成功回执中的当前境界会显示读取失败，不会误显示为未知境界。
- 乾坤袋库存读取失败时会明确提示稍后重试，不会把数据库异常误显示为空背包。
- `我的信息` 会展示账号状态、斗气档案、今日净修为和体内丹毒沉淀；本地档案、斗气档案、播放异常临停、ABS 服务端 `isActive`、今日净修为或丹毒计数读取失败时会明确提示，不会误显示为无资产、正常、未知境界、0 小时或 0 次丹毒。
- 今日净修为刷新严格读取北京时间当天 `YYYY-MM-DD`，不从昨天、明天或 UTC 日期取最大值，也不把历史会话当作实时播放源；如存在通过保守校验的跨日会话，则先在 ABS 官方 `days` 总量内守恒重分配后读取当天值。ABS 成功返回 `days` 但当天键缺失时按 0 写入；单日原始听书仍最多按 24 小时计入。

- 世界 Boss 的有效参与者有 `10%` 概率获得当前境界对应至宝；至宝禁止上架交易行，禁止积分代购。每次突破消耗、渡劫费用、成功率、冷却和失败保底规则保持现有配置。

## 求书

- 求书链接仅支持 `https://` 的 `ximalaya.com`、`www.ximalaya.com`、`m.ximalaya.com`、`xima.tv`，路径应为专辑首页，不能为专辑中单集的地址。
- 链接不得包含空格、换行、制表符、URL 账号密码信息或其他控制/分隔字符。
- 提交求书需要消耗积分：白名单用户每次 `10` 积分，周限 `3` 条、月限 `10` 条；有效期大于等于 3 个月（含永久）用户每次 `15` 积分，周限 `3` 条、月限 `5` 条；有效期小于 3 个月用户每次 `20` 积分，周限 `1` 条、月限 `3` 条；同时仍受待处理工单上限 `5` 条约束（`待接单` 与 `需补充信息` 状态均计入该上限，`处理中` 不计入）。
- 求书备注、补充信息、管理员备注和要求补充说明最多 300 字，可换行，但不得包含制表符或其他控制字符。
- 工单状态：`pending 待接单` → `claimed 处理中` ⇄ `need_info 需补充信息` → `uploaded 已上传` / `rejected 暂无资源` / `cancelled 已取消`；创建时实际扣除的积分会记录在工单上，取消或暂无资源时按原额退还（`uploaded` 不退），退还记录与状态变更在同一事务提交，`RefundedAt` 幂等防止重复退款。
- 用户可在 `我的求书` 中对仍处于 `待接单` 的工单自行取消（二次点击确认）；管理员在工单键盘上可 `取消工单`（需输入至少 5 字原因）。
- 滞留巡检（每小时）：`pending` 超 24 小时无人接单提醒管理员（最多 2 次）、`claimed` 超 48 小时未处理提醒接单人（最多 2 次），均不自动收尾；`need_info` 超 24 小时未补充提醒用户，超 48 小时仍未补充则自动取消并退还积分。
- 提交求书、补充信息、管理员接单、添加备注、要求补充、标记已上传/暂无资源或取消工单时，工单状态、处理日志和审计会在同一数据库事务内提交；若日志或审计暂时写入失败，本次操作会提示失败并保留原状态，避免工单缺少追溯。
- 管理员标记“已上传”后，系统会对每个 ABS 媒体库按每页 20 条、最多 10 页查询近 20 分钟内的新书；候选按稳定快照每页展示 10 个。候选快照和选择/预览 token 会以不透明 token 写入 SQLite，有效期 24 小时，进程重启后仍可继续操作；后台还会持久化最近 72 小时的 ABS 入库事件作为本地兜底，管理员不必受 20 分钟窗口限制；预览 token 同时保存所选书籍的公开 ABS 元数据，发布时不再依赖第二次 ABS 读取；过期、候选为空或读取失败时可重新读取。
- 每条预览和群公告都包含唯一凭证 `BR-<工单ID>`。公告发送使用持久化 `pending/sending/sent/failed/uncertain` 状态和工单唯一约束；Telegram 明确拒绝可重试，且明确失败最多自动重试 3 次；超时、限流、服务端或网络错误会停止自动重发。超级管理员须先在目标群搜索唯一凭证，再私聊执行 `公告异常已发 <工单ID> <Telegram消息ID>` 或 `公告异常未发 <工单ID>`，并按提示二次确认；状态、业务日志和 `AuditLog` 在同一事务登记。Telegram 与 SQLite 仍无法组成真正的分布式原子事务，因此人工核查是模糊结果的最终闭环。
- 发送中的持久化 lease 超过 5 分钟仍未完成时会自动转为 `uncertain`，不会自动重发；若 Telegram 已返回消息 ID 但 SQLite 成功日志提交失败，Bot 会尽量保存该消息 ID 作为人工核查证据。

## 群内寻宝

- 入口：`活动 -> 群内寻宝（积分小游戏）`，用于群内限时积分互动；个人抽取续期卡或邀请码请使用 `资产交易 -> 权益盲盒（续期卡/邀请码）`。
- 群内发送 `发起寻宝` 或 `寻宝`，同群共享 9 个宝箱，60 秒后或开满时结束；`寻宝状态` 查看本群最新一局。
- 每人每局只能开一箱，点击未开宝箱即消耗 `3` 积分并立即获得箱内奖励；奖励为 `0` 分 ×4、`2` 分 ×3、`5` 分 ×1、`10` 分 ×1，净盈亏为 `-3/-1/+2/+7` 分。奖励位置在开局时固定，重启不会重抽；未开箱不扣费。
- 每群北京时间每天最多 3 局，同群只能进行一局，结束后冷却 1 分钟；共用一张面板展示开箱结果，结束后揭晓剩余宝箱。
- 整局结算时，`总消耗 - 总奖励` 的正差额全部进入天道奖池；奖励超过消耗的部分由系统补贴，不扣减天道奖池。9 箱全开时总消耗 27 分、总奖励 21 分，6 分进入天道奖池。
- 开箱记录、扣费和奖励在同一事务提交，重复点击、抢同一箱、余额不足或流水写入失败不会重复扣费；奖池注入与整局结束状态在同一事务提交，重启会继续结算到期局。

## 卡密回收

在私聊打开 `资产交易 -> 卡密回收`，或发送 `卡密回收` / `回收卡密`。Bot 只接受本服生成且当前真实可用的邀请码、续期卡；输入完整卡密后会显示报价，回复 `确认回收卡密` 才会入账，回收成功后卡密立即失效且不可撤销。

回收价为当前配置定价的 60%：邀请码按当前邀请码价格计算；续期卡按当前 30 天续期价格和卡片天数折算后计算。默认定价下，邀请码回收 180 积分，3/30/90/365 天续期卡分别回收 9/90/270/1095 积分。实际以确认前 Bot 报价为准，若确认期间价格变化会中止并要求重新报价。

积分兑换的卡密和经过交易行成交的卡密只允许当前持有人回收，报价和确认都会校验归属，旧持有人不能凭保存的明文回收买家的卡密。其他未登记归属、未经过交易行成交的卡密仍采用持有码规则，请妥善保管明文；同一卡密只会成功回收一次。若卡密正在交易行出售，成功回收会同步关闭对应可售卡密，避免继续成交。
## 交易行

- `交易行 关键词` 可按商品名或背包物品名筛选，关键词为 1-40 个字。
- 筛选关键词不得包含换行、制表符或其他控制/分隔字符。
- `上架商品` 私聊分为自由卡密和背包上架：自由上架商品名为 2-40 个字，背包物品名为 1-40 个字，二者都不能包含换行、制表符、其他控制字符或 Unicode 行/段分隔符。
- 背包丹药商品会在交易行列表、详情、购买确认、购买成功、卖家成交通知和上架提醒中显示简要功效，方便买卖双方确认用途；自由卡密同名商品不显示系统丹药功效。
- 自由卡密仅允许上架 Bot 生成且尚未使用的邀请码/续期卡，成交前会再次复核仍未使用；积分兑换及已经过交易行成交的卡密只能由当前持有人上架，所有成交卡密归属转给买家；复核失败会中止交易并暂停该商品待核查。
- 交易行商品单价必须保持在系统原价值的 `85%`-`115%` 范围内；邀请码/续期卡按当前系统价格折算，背包物品按系统可识别的商城价、种子价、药草基础价或炼丹成本价折算，无法识别原价值的特殊物品仍受全局价格上限限制但不套用原价值区间。
- 交易行库存读取失败时会明确显示读取失败或提示库存状态暂不可用，不会把查询错误当成无库存或可购买。
- 管理员查询交易订单时，争议记录读取失败会明确显示读取失败，不会把数据库异常误显示为无争议记录；超级管理员可私聊使用 `强制下架商品 商品ID`，输入原因并二次确认后强制下架在售商品。
- 交易行商品有效期为 48 小时；到期后 Bot 自动下架，背包商品未售库存会退回卖家乾坤袋；商品售罄后会自动结束在售状态，不会再发送到期下架提醒。
- 若商品卖家数据出现不一致，系统会暂停该商品交易并通知管理员核查，不会继续自动下架或错误退回库存。

## 个人邀请拉新

- 达到斗者初期及以上的正式用户，私聊发送 `我的邀请`、`邀请链接` 或 `拉新链接` 可获得个人邀请链接。
