# 2026-11-19 斗气配置修复

现象：自动刷新每五分钟报 `major 12 requires 1 minor stages`，缓存使用内置兜底。

原因：旧库使用半帝=12、斗帝=13；当前程序使用斗帝=12。初始化只补缺失行，不转换旧行，造成旧四阶段与新九星配置混合。仅处理第12境界后，还会遇到低境界阶段门槛倒序。

处置：先执行 `./deploy.sh backup`，另用 SQLite `.backup` 留存一致性快照。对副本执行针对旧布局的一次性 SQL 修复，并用 `LoadCultivationRulesFromDBHandle` / `ValidateCultivationRuleSet` 验证，确认通过后对生产库执行同一事务。脚本校验旧布局并要求没有11级及以上玩家，避免错误转换玩家境界。已执行的脚本归入本地运维档案，不随项目提交或发布。

变更：境界名称和阶段门槛对齐当前内置规则，斗圣区间延长至22300小时，第12境界改为单阶段斗帝，软删除第13境界及多余阶段；斗圣突破目标保持12，门槛22300，丹药为古帝源气；软删除旧12→13突破。其他突破参数、用户修为、积分、订单均保留。无需重启，等待五分钟缓存刷新。

边界：这是针对已确认历史数据布局的一次性修复，不是通用自动迁移。新建库无此问题；其他历史库需先检查并备份，不能直接批量运行。

另发现旧群 `-5429117438` 在 `title_groups` 中名为“昔风，昔风听书助手以及Arukoii”。`runtime.go` 对收到消息的群调用 `titles.TrackMember`，自动记录群和成员，与 `.env` 的官方群设置不同。Telegram 返回该群已删除；仅凭数据库不能判断其删除或迁移经过。最初检查未修改旧群记录；用户随后授权清理所有非官方群称号记录，备份后删除旧群群记录、成员关联及佩戴各一条。程序同步范围已限定为当前官方群，启动时清理其他群的称号数据。
