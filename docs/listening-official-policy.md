# ABS 每日修为与历史修复

普通刷新只取 ABS `listening-days` 的北京时间当日汇总，历史修为沿用数据库内已保存的日账目和累计差额。不再请求近期会话分页，不做跨天重分配、重叠扣除或历史会话校验。播放异常巡检直接读取系统已保存的每日报告原始时长，不再按会话拆日。会话证据仍用于闭关和显式历史修复；这些任务失败不再阻断普通每日修为刷新。

## 日常计算

- 原始秒数保留 ABS 最新值；认可秒数只增不减。今日最多零点到校验时刻的秒数，历史最多 86400 秒，未来日期不计入。无效日期、负值、非有限值、显式 null 拒绝整份普通统计。
- 对每日累计认可秒数整体执行现有分段折算，不对每次增长单独从第一档折算。该日的异火和宗主资格仍按历史快照，闭关只按独立证据发放。
- 每日修为减去该日已入账修为，得到累计修为的差额。日期账目、累计档案、贡献、升级事件、报告统计快照同事务提交。
- 北京时间零点为绑定账号持久化按账号、ABS 绑定和日期唯一的收尾任务，缺少昨日日账时也会创建任务。采样、差额结算、日账归档和任务完成在同一事务提交。启动时补建漏过的日期，已有未归档账目加入队列，失败项每分钟按原日期重试，后续跨日和重启继续处理。普通刷新只写今日，昨日收尾不更新今日报告的同步时间。
- ABS 时长减少时记录 `official_decrease_retained` 并显示保留已认可时长的提示；按日请求缺少指定日期视为同步失败，明确返回数字零代表无播放。真实多报需要管理员另行审计纠正，不能后台静默扣回。
- 同一账号的请求按请求开始时刻排序，拒绝旧响应。跨午夜才返回的统计需要按新日期重新采样。ABS 的日期归属沿用其会话记录的日期字段。
- ABS 在数据库内按用户和日期汇总，不加载会话对象。Boss 和秘境的历史活动进度也只沿用已保存的快照。独立的历史会话修复可取跨日期汇总以核验凭据。

## 迁移基线

新增字段由启动 AutoMigrate 创建：

- `cultivations.official_daily_initialized`、`official_daily_abs_user_id`：记录当前账号完成切换。
- `official_daily_baseline_before`：持久化迁移或换绑的北京时间日期边界，常规刷新不推进；原生新政策账号为空。
- `daily_listening_stats.official_policy`：该日是否采用新政策。
- `official_baseline_seconds`：同账号迁移时取旧统计已经观察到的官方秒数与认可秒数的较大值；换绑时取新账号首次观察的认可秒数。
- `official_baseline_hours`：切换时已有的普通修为。
- `official_baseline_credited_seconds`：旧加成使用的认可秒数。

正常切换保留已结算余额。迁移日的普通修为为：

```
旧普通修为 + f(当前认可秒数) - f(迁移基线秒数)
```

换绑时，旧账号已获得的普通修为和加成计算基数继续保留，但新账号的时长基线、认可时长独立建立，不继承旧账号的时长高水位。例如旧账号已有 10 小时，新账号首次 1 小时不重复导入，之后从 1 小时增至 2 小时，补入 `f(2 小时) - f(1 小时)`。新账号自身后续减少时仍保留其认可高水位。

加成的秒数基线也保留，防止历史差额通过异火或闭关被间接补发。新增加的秒数仍按同一日正常折算。首次切换已有档案或更换 ABS 账号时，持久化切换日期边界。无论历史来源日在首次响应中出现，还是迁移完成后延迟补报，只要此前无账目且日期早于该边界，就先建立零修为基线，之后仅补该日新增差额，避免与旧跨天分配重复入账。边界及之后的日期正常结算，边界不会随常规刷新推进。原生新政策账号不设置迁移边界，日常刷新仍只处理当天。

迁移不是历史补偿；原本少算的部分保留为可审查差额。不应先用 SQL 把全历史替换成新算法结果。

## 历史修复工具

构建：

```sh
go build -o listening-repair ./cmd/listening-repair
```

先上线新代码并让目标账号成功同步，确保新政策基线与每日加成快照已经建立。数据库需要一致备份。默认预览使用 SQLite `mode=ro`，不执行迁移、不调用 ABS、不发送 Telegram 消息：

```sh
./listening-repair -db /path/to/bot_data.db -user 5137419108 -day 2026-11-17
```

输出包括基线秒数、修复前后普通修为、`BaseDeltaHours`，以及考虑加成后的累计修为前后值和 `TotalDeltaHours`。

核对每日原始值、旧账目、跨天来源与历史加成后，使用预览中的精确基础差额：

```sh
./listening-repair -db /path/to/bot_data.db -user 5137419108 -day 2026-11-17 \
  -apply -expected-delta 3.5281666666666665 -actor OPERATOR_TG_ID \
  -reason '核对 ABS 每日原始统计后，修复旧跨天保守校验少计'
```

`OPERATOR_TG_ID` 必须替换成实际操作人的数字 ID。示例差额只对应本次取证快照，正式操作必须重新预览。

工具仅释放选定日期的迁移差额，不重新导入整份 ABS 历史。基础差额变化、每日未结算、会降低总修为、影响其他未结算日期时拒绝提交。成功操作与 `REPAIR_OFFICIAL_LISTENING_DAY` 审计同事务保存。重复执行原预览不能重复补偿；修复后日常刷新沿用修复结果。

## 离线回放

可对一致 SQLite 备份执行真实账目回放，测试会先复制到临时目录，源备份只读：

```sh
CCOFF_LISTENING_REPLAY_SNAPSHOT=/path/to/snapshot.db \
CCOFF_LISTENING_REPLAY_USER=5137419108 \
go test ./internal/game -run '^TestOfficialDailySnapshotReplay$' -v -count=1
```

2026-11-18 取证副本中，该用户切换前累计为 53.935604285714 小时，单纯切换保持不变。按新政策核对历史可见 6 个待审查差额日，基础差额合计约 26.391459 小时。其中 11 月 17 日约 3.528167 小时。它们是旧算法与新政策的差额，不等于已经逐日证明的客户端误算；正式补偿需要逐日审查。

以上回放没有修改生产数据库，也没有执行生产补偿。临时副本和日志可能包含账号数据，应限制访问。

### 闭关证据异常隔离

普通统计刷新和每日灵火刷新，只在计算对应日期的闭关加成时解析相关证据。历史无关记录的 JSON 损坏或无效日期不会阻断普通统计事务。相关证据异常时记录日志，冻结该日已结算的闭关加成（没有已结算加成则按零处理），普通听书增量继续结算。冻结整日闭关分量，避免与其他有效闭关重复叠加；证据修复后，版本变化会触发重新结算。数据库错误仍按事务规则回滚，秘境等操作的累计修为核验、闭关证据采集和历史修复工具仍保留严格校验。

### 换绑额度和闭关起点

换绑保留的日修为与新账号增长共用 Telegram 用户当日 8.5 小时的基础修为上限，反复换绑不会重置额度。个人闭关、宗门闭关均以 `BonusListeningSeconds()` 保存起点，与闭关加成使用同一秒数口径，避免迁移时官方统计与旧认可秒数的差额吞掉后续闭关增长。

### 历史修复的基线来源限制

每日记录持久化 `OfficialBaselineKind`，区分 `legacy_migration`（旧政策迁移）、`rebind`（换绑）、`native`（新政策原生记录）、`historical_excluded`（为防止重复结算而排除的历史来源日）。正常刷新保留来源，换绑时改记为 `rebind`。历史修复的预览和执行只接受明确的 `legacy_migration`；换绑时有意排除的账号历史不属于欠账，也不能通过修复恢复其加成秒数。已有新政策记录如果来源为空，保持未知并拒绝自动修复，需要先核查原始迁移/换绑记录，不能仅凭数值差额推断来源。原始旧政策记录首次迁移时会正常写入来源。

### 播放异常巡检与报告一致

巡检使用当前绑定 ABS 账号的 `daily_listening_stats.raw_seconds`，与听书报告展示的原始时长一致；不使用 `capped_seconds`、净修为或按会话首尾推算的自然日时长，也不主动刷新已保存报告。昨日报告超过 15 小时提醒；昨日和前日两份报告都超过 15 小时才临停。恰好 15 小时不触发。缺失、已删除、未成功同步或其他绑定账号的报告不能作为超限依据；相关日期仍有待收尾任务，或新政策日账尚未归档时，保留巡检进度并按 5 分钟间隔重试；同轮其他账号继续巡检。数据库读取失败也保留巡检进度。

例如，11 月 20 日保存的报告为 52218 秒（14.505 小时），即使跨日会话能推算出该自然日播放至少 22.74 小时，也不触发该日提醒。提醒和临停审计记录 `basis=saved_report_raw_seconds`，用于区别历史会话口径的记录。

### 任务与活动输入一致性

宗门每日听书任务刷新后直接读取保存的普通修为与闭关加成，与缓存路径一致，不重新折算认可秒数，避免绕过迁移或换绑基线。异火和宗主加成仍不计入该任务。

闭关凭据由独立后台任务采集，不依赖异常巡检或已完成的历史扫描。每次每条闭关最多读取 5 页会话，按 5 分钟间隔持久化游标续扫；凭据、游标和加成结算在同一事务提交。闭关期间及结束后 24 小时内重复扫描以接收延迟上传，之后完成最后一轮；旧闭关没有采集游标时也会补扫。会话读取失败保留已保存报告和扫描进度，不阻断普通修为刷新。

闭关采集与结算遵守全量刷新至称号发布的隔离锁。尝试时间在分页事务之外单独保存，凭据或结算写入失败也按 5 分钟间隔重试，避免失败记录反复占满批次名额并阻塞其他用户。

普通刷新和秘境快照共用每日统计解析器。显式 `null`、非法日期、负值、类型错误及数值溢出在写入前拒绝，保留上次成功报告及其同步时间；数字 `0` 仍作为明确修正处理，并遵守认可时长只增不减的规则。

热门书单通过 `listening-sessions` 每页 100 条读取完整历史，按统计周期筛选并按会话 ID 去重，不使用仅含最近 10 条的 `recentSessions`，也不套用普通证据扫描的 5 页限制。任一账号分页读取失败，本期不展示书单排名，个人净修为榜仍可使用已保存的账目。
